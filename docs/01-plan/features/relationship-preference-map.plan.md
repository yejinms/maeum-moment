## 1. Overview

### 1.1 Purpose

연애 상대를 떠올리며 구체적인 장면 속 두 행동을 선택하게 하고, 사용자가 사랑을
받을 때와 표현할 때의 상대적 우선순위 및 원하는 행동을 발견하도록 돕는다.

### 1.2 Background

“말보다 실제로 도와줄 때 사랑을 더 크게 느끼는가?” 같은 추상 질문은 사용자가
자기 경험을 떠올리기 어렵고 모든 항목을 중요하다고 평가하게 만든다. 반면
연애 밸런스 게임은 시간, 장소, 사건과 두 개의 현실적인 선택지를 제공해 사용자가
구체적인 장면에 반응하도록 만든다.

본 서비스는 기존 분류를 과학적 진단이나 고정 성격 유형으로 제시하지 않는다.
사용자가 현재 관계에서 중요하게 느끼는 행동을 대화 가능한 형태로 정리하는
자기성찰 도구를 목표로 한다.

## 2. Product Definition

### 2.1 One Concrete Job

> 현실적인 연애 장면을 선택해 내가 받고 싶은 사랑 또는 자연스럽게 표현하는
> 사랑의 우선순위를 먼저 발견하고, 원할 때 두 결과의 차이까지 확인한다.

### 2.2 Target User

- 사랑 표현 방식의 우선순위를 정하기 어려운 성인 사용자
- 연애 중이거나 특정 상대를 떠올릴 수 있는 사용자
- 결과를 대화의 출발점으로 사용하려는 개인 또는 커플

### 2.3 Decision Unit

- 단위: 동일 상황에서 제시되는 두 개의 구체적 행동 중 하나 선택
- 비교 축: 인정하는 말, 함께하는 시간, 의미 있는 선물, 실제적인 도움, 동의된 접촉
- 방향: `receive`(받을 때)와 `express`(표현할 때)를 분리
- 확신도: `close`(간발의 차이), `clear`(확실히 이쪽)

## 3. Goals

### 3.1 Primary Goals

- [x] 추상적 질문을 시간·장소·사건이 포함된 장면형 문항으로 전환한다.
- [x] 받는 선호와 표현 습관을 별도 트랙으로 측정한다.
- [x] 사용자의 선택을 1~5위와 실제 행동 예시로 변환한다.
- [x] 결과의 점수 차이와 응답 일관성을 함께 표시해 과도한 단정을 피한다.
- [x] 모바일에서 한 손으로 진행 가능한 몰입형 밸런스 게임 경험을 제공한다.

### 3.2 Non-Goals

- 심리검사, 진단, 치료 또는 관계 만족도 예측
- 공식 Five Love Languages 퀴즈의 복제·각색
- 사용자 간 백분위 또는 다른 사람과의 우열 비교
- 로그인, 서버 저장, 커플 계정 연결
- 결제, 광고, 관리자 페이지

## 4. Scope

### 4.1 In Scope

- 시작 화면 및 서비스 한계 안내
- 받는 테스트/표현하는 테스트 시작 순서 선택
- 받는 사랑 20문항
- 표현하는 사랑 20문항
- 한 테스트 완료 직후 단독 결과 제공
- 나머지 테스트 추가 진행 선택
- 최근 결과, 이전 결과, 통합본 순서의 최종 결과
- 트랙별 진행률, 이전 문항 이동, 자동 임시 저장
- A/B 선택 및 선택 확신도 기록
- 트랙별 순위, 점수 차이, 상황 의존성 안내
- 받는 방식과 표현 방식의 차이 요약
- 사용자가 선택한 구체적 행동 카드
- 결과 텍스트 복사 및 Web Share API 공유
- 모든 응답 초기화
- 반응형·키보드 접근 가능한 정적 웹앱

### 4.2 Out of Scope

- 커플 결과의 서버 기반 실시간 비교
- 소셜 로그인과 클라우드 동기화
- 인공지능 해석 또는 상담 챗봇
- 다국어 지원
- 공개 결과 URL 및 분석 대시보드
- 임상적 신뢰도·타당도 주장

## 5. Functional Requirements

| ID | Requirement |
|---|---|
| FR-01 | 사용자는 받는 테스트와 표현하는 테스트 중 원하는 하나를 먼저 선택한다. |
| FR-02 | 각 트랙은 다섯 범주의 모든 10개 조합을 서로 다른 맥락에서 두 번 제시한다. |
| FR-03 | 문항은 장면, A 행동, B 행동, 범주 메타데이터를 가진다. |
| FR-04 | A/B 위치와 문항 순서는 고정 시드 기반으로 섞어 위치 편향을 줄인다. |
| FR-05 | 선택 후 `간발의 차이` 또는 `확실히 이쪽`을 기록할 수 있다. |
| FR-06 | 이전 문항으로 돌아가 선택을 수정할 수 있다. |
| FR-07 | 새로고침 후 진행 상태가 복구된다. |
| FR-08 | 단순 승수와 확신도 가중치를 이용해 개인 내 상대 순위를 산출한다. |
| FR-09 | 동점이나 비일관 응답은 오류가 아니라 `상황에 따라 달라짐`으로 설명한다. |
| FR-10 | 한 트랙 완료 즉시 해당 순위와 행동 예시를 표시하고 나머지 트랙 진행 여부를 묻는다. |
| FR-11 | 결과 요약을 복사하거나 지원 기기에서 공유할 수 있다. |
| FR-12 | 사용자는 저장된 응답을 명시적으로 초기화할 수 있다. |
| FR-13 | 두 트랙 완료 시 방금 완료한 결과, 이전 결과, 두 방향 통합본을 순서대로 표시한다. |

## 6. Non-Functional Requirements

- 첫 화면은 일반적인 모바일 네트워크에서 빠르게 표시되어야 한다.
- 서버 전송 없이 브라우저에서만 동작해야 한다.
- 360px 이상 화면에서 가로 스크롤이 없어야 한다.
- 모든 선택과 이동은 키보드로 가능해야 한다.
- 색상만으로 선택 상태나 순위를 전달하지 않아야 한다.
- `prefers-reduced-motion` 환경에서 불필요한 애니메이션을 제거해야 한다.
- 결과를 “진단”, “정답”, “궁합 보장”으로 표현하지 않아야 한다.
- 접촉 문항은 동의된 비성적 접촉만 사용해야 한다.

## 7. Scoring Principles

- 5개 범주의 전체 조합 수는 10개이며 각 조합을 트랙당 2회 제시한다.
- 선택한 범주에 기본 1점을 부여한다.
- `확실히 이쪽`은 1.25점, `간발의 차이`는 1점으로 계산한다.
- 총점은 해당 범주가 등장한 문항 수로 나누어 0~100 상대 점수로 변환한다.
- 같은 범주 쌍의 두 문항에서 선택이 갈리면 맥락 의존 신호로 기록한다.
- 1위와 2위 차이가 5점 미만이면 공동 핵심 선호로 안내한다.
- 결과는 같은 사용자 내부의 상대 순위로만 해석한다.

## 8. Success Criteria

- [ ] 받는 트랙 20문항과 표현 트랙 20문항이 모두 동작한다.
- [ ] 어느 트랙이든 먼저 선택해 완료하고 해당 단독 결과를 즉시 볼 수 있다.
- [ ] 두 번째 트랙은 사용자가 선택한 경우에만 진행하며 완료 후 통합본을 표시한다.
- [ ] 10개 범주 조합이 각 트랙에서 정확히 두 번씩 등장한다.
- [ ] 응답 저장, 이전 이동, 재접속 복구가 동작한다.
- [ ] 결과 순위와 선택 행동이 입력 데이터에서 재현 가능하게 계산된다.
- [ ] 360px, 768px, 1280px 화면에서 핵심 플로우를 완료할 수 있다.
- [ ] 키보드만으로 온보딩부터 결과까지 완료할 수 있다.
- [ ] 결과 화면에 비진단적 한계 안내와 개인정보 로컬 저장 안내가 노출된다.
- [ ] 자동화된 데이터 무결성 검사와 핵심 점수 계산 테스트가 통과한다.
- [ ] 디자인-구현 갭 분석 일치율이 90% 이상이다.

## 10. Risks & Mitigations

| Risk | Impact | Probability | Mitigation |
|---|---|---|---|
| 공식 퀴즈·상표와 혼동 | High | Medium | 독자 이름·문항·결과 문구 사용, 출시 전 법률 검토 |
| 선택지 노력·비용 불균형 | High | High | 동일 장면·유사 강도 원칙과 문항 리뷰 체크리스트 적용 |
| 40문항 이탈 | Medium | Medium | 트랙을 독립 테스트로 분리하고 20문항마다 결과 제공, 두 번째 테스트는 선택 진행 |
| 고정 유형으로 오해 | High | Medium | 선호 지도·상황 의존성·점수 차이 표시 |
| 접촉 문항 불편 | Medium | Medium | 동의된 비성적 접촉, 문항 건너뛰기 대신 사전 안내 및 초기화 제공 |
| 단순 점수의 과도한 정밀성 | Medium | Medium | 개인 내 순위만 제공하고 신뢰도 표현을 정성화 |

## 11. Architecture Considerations

- Starter 수준의 HTML/CSS/JavaScript 정적 애플리케이션
- 평가 문항과 계산 로직을 UI 렌더링과 분리
- 브라우저 `localStorage`에 버전이 포함된 단일 상태 객체 저장
- 빌드 도구 없이 로컬 HTTP 서버 또는 정적 호스팅에서 실행 가능
- Node 내장 테스트 러너로 데이터 및 점수 로직 검증

## 12. Convention Prerequisites

- 파일명: kebab-case
- JavaScript 함수/변수: camelCase
- 상수: UPPER_SNAKE_CASE
- 범주 키: `words`, `time`, `gifts`, `service`, `touch`
- 트랙 키: `receive`, `express`
- UI 텍스트는 한국어, 코드 식별자는 영어
- 문항 ID: `{track}-{pair}-{index}` 형식
